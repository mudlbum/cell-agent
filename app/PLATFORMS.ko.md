# 플랫폼 확장 계획

현재 공개 가능 범위: Windows Python 실험판. 반응형 웹사이트는 브라우저에서 접근할 수 있지만 그것이 모바일 실행 엔진의 완성을 뜻하지 않는다.

## 공통 계약

대화와 실행 요청, 작업 상태, 명령 승인, 아티팩트 조회, 중단, 절차 공유를 버전이 있는 JSON 계약으로 분리한다. 모델 키는 클라이언트 소스에 넣지 않고 실행 노드에 보관한다. 로컬 루프백 API를 그대로 외부 공개하지 않고 기기별 인증·짧은 수명의 권한·TLS·회수 기능을 갖춘 게이트웨이를 별도로 구현한다.

## 순서와 출시 조건

1. Windows: 상태/데이터 마이그레이션, 독립 설치 패키지, 서명된 업데이트, 중단·복원 회귀 검증. 현재 ZIP/Python 방식에서 패키징을 확장한다.
2. macOS: Windows Job Object와 msvcrt 잠금을 플랫폼 추상화로 분리. launchd/프로세스 그룹의 한계를 검토하고 자식 프로세스 탈출·충돌·종료를 실기기로 검증. 앱 서명·공증과 사용자 권한 요청을 구현한다. 검증 전 Windows와 같은 격리/자원 제한을 약속하지 않는다.
3. 모바일 공통: 대화·파일 선택·승인·중단·결과 조회 클라이언트를 먼저 만든다. 사용자 소유 실행 노드와 암호화된 기기 페어링을 수행한다. 모바일의 전원·배터리·백그라운드 제약 때문에 장시간 작업은 연결된 PC/서버에 맡긴다. 노드가 오프라인이면 실행하지 않고 상태를 명확히 표시한다.
4. Android: 플랫폼 저장소/백그라운드 규칙에 맞는 권한, 서명된 APK/AAB, 업데이트 무결성, 실제 기기·배터리 테스트.
5. iOS: 앱 샌드박스에 맞는 파일 선택과 백그라운드 전략, APNs 알림을 도입할 경우 명시적 동의, TestFlight/스토어 심사, 실기기 테스트. 임의의 OS 전체 접근이나 무한 백그라운드 실행을 목표로 하지 않는다.

## 피어 공동 성장의 다음 단계

현재: 절차를 선택 게시 → 상대 서명 검증 → 격리 → 후보 등록 → 로컬 검증. 두 로컬 노드의 HTTP 교환을 테스트했다. 공개 인터넷의 운영 신뢰성은 검증하지 않았다.

다음: 재현 가능한 평가 패키지, 데이터 유출 검사, 악성 절차 시험, 서명 키 회수/교체, 패키지 만료와 게시 철회, 다중 원본의 복구, 네트워크 쿼터, 패키지별 출처 표시와 평가 이력. 서로 다른 기기의 코드를 자동 실행하는 기능은 이 검증 경계와 격리 체계가 먼저 갖춰져야 한다.

모델 가중치 공동 학습은 별도의 연구 과제다. 개인정보·라이선스·데이터 중독·비잔틴 노드·검증 비용을 해결하기 전까지 현재의 경험 공유를 연합 학습이나 지능 향상으로 표현하지 않는다.
