# 성장하는 세포 에이전트: 구현 경계와 검증 계획

## 두 층의 책임

**제어 계층:** 사용자 목표와 완료 기준, 프로세스 생명주기, 권한 선택, 예산, 명령 승인, 비상 정지, 검증 기록을 관리합니다. `dashboard.py`와 Windows `process_guard.py`가 담당합니다.

**작업 계층:** 요구에 따라 역할을 분화하고, 모델과 도구로 작업하며, 기억과 탐색 경로 후보를 제안합니다. `dashboard_worker.py`, `cell_agent.py`, `growth.py`가 담당합니다.

작업자는 API 키나 목표를 받기 전에 프로세스 그룹에 배치됩니다. 제어 계층은 작업자의 모델 응답을 기다리지 않고 작업 그룹을 종료할 수 있습니다. 작업자에게 평가 통과 도구나 비상 정지 해제 도구를 제공하지 않습니다. 이것은 인터페이스상의 책임 분리이며, 같은 OS 사용자로 실행되는 적대적 코드에 대한 격리 보장은 아닙니다.

## 상태 전이

```text
준비 → 실행 ↔ 경계 일시정지
         ├→ 보고 완료 → 사용자 평가: 통과/실패
         ├→ 실패
         └→ 비상 정지 → 정지 잠금 → 사용자 해제 → 새로운 작업
```

서버 재시작으로 끊긴 작업은 자동 재개하지 않습니다. 도구 실행이 정확히 한 번 수행되었는지 일반적으로 증명할 수 없기 때문입니다. 로그와 파일 변경 기록을 확인한 뒤 새 작업을 시작합니다.

## 취약점과 현재 대응

| 실패 가능성 | 현재 구현 | 남은 한계 |
|---|---|---|
| 자신이 잘했다고만 말함 | 보고 완료와 사용자 평가 분리 | 독립 자동 벤치마크 러너는 미구현 |
| 잘못된 지식 반복 | 출처·가설 구분·경로 검증 절차 | 출처 자체의 진실성을 자동 보증하지 않음 |
| 문서 링크 소멸 | 재검색 전략·대체 경로 보존 | 원자료가 모두 사라지면 복원 불가 |
| 오래된 경험 오용 | 적용 문제·버전·검토 시각 기록 | 자동 버전 호환성 판정 미구현 |
| 평가 기준을 바꿔 성공 주장 | 사용자 완료 기준과 리뷰 인터페이스 분리 | trusted 호스트 권한 자체는 DB 위변조를 격리하지 않음 |
| 분열 폭증 | 깊이·개수·공유 호출 예산·OS 프로세스 제한 | 많은 작은 요청의 누적 운영비는 별도 관리 필요 |
| 자원 고갈 | 작업 그룹 CPU/메모리 제한·실행 시간·저장량 검사 | 파일시스템 하드 쿼터와 정확한 달러 한도 없음 |
| 같은 파일 충돌 | 파일 도구 직렬화·복구 시 내용 해시 비교 | 외부 프로그램 변경, 긴급 종료 중 경쟁을 완전히 해결하지 않음 |
| 작업 중 종료 | 변경 전 백업·의도 기록·원자적 교체 | 외부 API와 일반 셸 부작용은 자동 복원 불가 |
| 멈추지 않는 모델 호출 | 제어 프로세스가 작업자 그룹 종료 | 이미 전송된 원격 계산은 남을 수 있음 |
| 화면이 닫힌 채 작업 지속 | 45초 제어 heartbeat와 정지 잠금 | 브라우저 절전은 보수적인 불필요 종료를 유발할 수 있음 |
| 제어 서버 중복 | 상태 폴더당 OS 파일 잠금 | 다른 상태 폴더는 별도 인스턴스이므로 합산 자원 감독 없음 |
| 웹 페이지가 명령을 주입 | 출처를 지시와 구분, 기본 명령 승인 | 모델 프롬프트만으로 모든 주입 공격 방어 불가 |

## 실제 성장을 입증하는 다음 실험

1. 사용자가 반복하는 작업 한 종류를 고릅니다. 예: CSV 변환 오류 진단.
2. 고정된 자원 예산으로 기존 에이전트의 기준선을 측정합니다.
3. 성공 사례뿐 아니라 오류·반례·중단 사례를 수집합니다.
4. 학습/절차 개선에 사용할 사례와 최종 평가 사례를 분리합니다.
5. 경로 재사용, 도구 코드화, 작은 판단 모델 중 가장 단순한 개선을 적용합니다.
6. 처음 보는 문제에서 정확도, 사용자 개입 횟수, 시간, 메모리, 토큰 비용을 비교합니다.
7. 기존 능력 회귀와 새로운 실패가 허용 범위를 벗어나면 채택하지 않습니다.

단일 데모 성공, 파일 수 증가, 내부 자기 평가 점수만으로 지능 향상을 주장하지 않습니다. 현재의 리뷰 기록은 실험을 준비하는 기반이며 통계적인 우위를 입증하지 않았습니다.

## 향후 기능과 명시적 비목표

다음 확장 지점은 외부 저장소 의미 검색, 경로 자동 재검증, 승인된 평가셋 러너, 모델별 어댑터, 작은 라우터의 학습입니다. GUI 화면 인식과 마우스 조작도 별도 드라이버가 필요합니다. 이 버전에는 Claude/Codex 앱 연동, 신경망 증류, 모델 가중치 변경, 무제한 상시 연구가 없습니다.

Windows 권한 상승·OS 정책 우회·모델 서비스 정책 제거를 성장 기능으로 구현하지 않습니다. 권한을 넓히는 결정은 사용자의 제어 영역입니다. 강한 격리가 필요하면 별도 계정 또는 VM으로 작업 계층을 이동해야 합니다.

## 기술 근거

- [Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects): 프로세스 그룹과 kill-on-close. 외부 서비스를 경유한 프로세스는 기본 상속 대상이 아닐 수 있습니다.
- [Job memory limits](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_extended_limit_information): 작업 그룹 커밋 메모리 제한.
- [CPU rate control](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_cpu_rate_control_information): CPU 비율 제한.
- [OpenAI function calling](https://developers.openai.com/api/docs/guides/function-calling): 모델의 도구 요청과 애플리케이션 실행의 분리.
- [OpenAI retrieval](https://developers.openai.com/api/docs/guides/retrieval): 의미 기반 검색의 향후 연결 지점. 현재 구현은 로컬 키워드 검색입니다.
