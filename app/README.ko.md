# Cell Agent 0.3 — 대화로 사용하고, 검증한 방법을 연결합니다

## v0.3에서 시작하기

기본 화면은 **대화**입니다. 질문과 작업을 보내고, 최근 대화 문맥을 이어가며 결과·진행 상태·명령 승인 요청을 확인할 수 있습니다. 대화는 로컬 SQLite에 저장하며 후속 요청에는 최근 12개 메시지(각 최대 4,000자)를 전달합니다. 전체 대화를 무제한 기억하는 것은 아닙니다. API 키는 설정 화면에서 적용하면 감독 서버 메모리에만 남고 서버 종료 시 사라집니다. 환경변수 키가 있으면 계속 사용될 수 있습니다.

실제 실행은 GPT-6 Astra에 접근할 수 있는 API 계정이 필요합니다. **고정 시나리오 데모는 질문에 답하는 LLM이 아닙니다.** 텍스트 파일 첨부는 UTF-8, 파일당 40 KB, 메시지당 최대 4개입니다. 작업자가 로컬 파일 경로를 읽도록 전달합니다. 대화와 파일 내용이 실제 작업 중 모델 API에 전송될 수 있습니다. 결과 텍스트는 완료 후 표시하고 진행 이벤트는 약 1초마다 갱신합니다. 토큰 단위 스트리밍은 아닙니다.

**연결과 공유**에서는 사용자가 검토한 탐색 절차만 게시합니다. 선택 기능의 설치:

```powershell
python -m pip install -r requirements-network.txt
python share_server.py
```

서명용 `cryptography`가 없으면 대화/작업은 계속 사용할 수 있지만 피어 공유는 비활성화됩니다. 공유 서버는 기본적으로 127.0.0.1:8766의 읽기 전용 피드입니다. 다른 컴퓨터의 공유 절차를 가져오려면 상대 HTTPS 피드와 직접 확인한 공개 키를 등록합니다. 피드를 인터넷에 제공할 HTTPS 프록시/인증 운영은 별도 설정이며 자동 배포하지 않습니다. **제어 서버 포트 8765를 인터넷에 노출하지 마세요.**

수신 패키지는 Ed25519 서명·SHA-256·발신자·스키마를 검사해 격리합니다. 검토 후 가져와도 로컬 후보일 뿐 자동 활성화하지 않습니다. 기존에 받은 패키지가 손상되거나 없어졌다면 ‘가져오기 / 손상 복원’이 같은 해시의 원본을 다시 요청합니다. 원래 피어가 해당 패키지를 계속 제공해야 합니다. 대화/개인 파일/모델 키는 피드에 자동 게시하지 않습니다. 공개할 절차의 민감 정보는 사용자가 확인해야 합니다.

이 버전은 블록체인, 원격 작업 실행, 바이러스 치료, 운영체제 전체 복구, 탈취된 키 복구를 구현하지 않습니다. 같은 Windows 계정의 악성 프로세스는 상태 DB와 서명 키를 변경할 수 있습니다. 서명은 발신자 증거이며 내용의 정확성·안전성 증거는 아닙니다. manifest 버전 감소와 같은 버전의 내용 변경을 거부하지만, 악성 발신자·공모·시빌 공격을 해결하는 신뢰 시스템은 아닙니다. 피어 최대 16개, 피드당 패키지 최대 64개, 한 번의 동기화에서 최대 4개를 수신합니다.

현재 감독 런타임은 **Windows 전용**입니다. macOS, Android, iOS 앱이 출시되었다고 표시하지 않습니다. 플랫폼별 구현 계획은 배포 홈페이지의 설치 안내와 `PLATFORMS.ko.md`에 있습니다.

**권장 시작: `control.cmd`를 더블클릭하세요.** 로컬 브라우저 관제 화면이 열립니다. 서버는 `127.0.0.1:8765`에만 연결하며, 시작 주소에 포함된 서버 시작 때 생성되는 세션 토큰으로 접근합니다. 화면을 다시 열어 인증이 필요하면 실행 터미널에 표시된 전체 주소를 사용하세요. API 키가 없어도 데모와 중단 실험을 사용할 수 있습니다.

## 새 관제 화면

- **관제실:** 목표·완료 기준 입력, 실행 권한/예산 설정, 세포 관계도, 도구 활동, 명령 승인, 결과 확인.
- **기억과 경로:** 출처가 있는 경험, 재사용 절차, 위치·재검색 전략·검증·대체 경로로 구성된 기억, 파일 변경 복구.
- **성장 평가:** 목표 완료 여부에 대한 사용자의 근거와 판정. 모델의 보고 완료와 실제 검증을 구분합니다.
- **실행 기록:** 최근 작업과 이벤트 조회. 이전 작업의 결과도 다시 볼 수 있습니다.

설치된 Python 3.10+ 외에 추가 패키지는 필요 없습니다. 관제 화면의 작업 감독 기능은 현재 Windows 전용입니다.

```powershell
python -X utf8 dashboard.py
python -X utf8 dashboard.py --port 8766 --root "D:\MyProjects"
```

브라우저를 열지 않고 서버만 시작하려면 `--no-browser`를 붙입니다. `--root`는 반복 지정할 수 있습니다. 관제 화면의 기본 데이터는 `state-ui/`, 파일 작업은 `workspace-ui/`에 저장합니다. 예전 CLI 데이터 `state/`와 분리되어 있습니다. 기존 CLI 상태를 사용하려면 모든 관련 실행을 종료한 후 `--state`로 명시하세요. 스키마는 기존 기록을 지우지 않고 확장합니다.

## 비상 정지는 어떻게 작동하나요?

관제 서버와 에이전트 작업자를 **별도 프로세스**로 실행합니다. 작업자에게 목표나 API 키를 전달하기 전에 Windows Job Object에 연결합니다. 기본적인 하위 프로세스도 이 작업 그룹을 상속합니다. 그룹에 연결할 수 없으면 작업을 시작하지 않습니다.

1. **일시정지:** 다음 모델 호출/도구 실행 경계에서 대기합니다. 이미 실행 중인 명령이나 외부 API 호출을 얼리는 기능이 아닙니다.
2. **비상 정지:** 확인 대화상자 없이 작업 그룹의 프로세스를 종료하고 작업자 종료를 확인합니다. 새 실행도 잠깁니다.
3. **잠금 해제:** 상태와 변경 내용을 확인하고 `RESUME`을 직접 입력합니다. 과거 작업은 자동 재개되지 않습니다.
4. **제어 연결 유실:** 인증된 화면 조회가 45초 동안 없으면 작업을 종료하고 잠급니다. 컴퓨터 절전이나 브라우저의 백그라운드 타이머 제한도 연결 유실로 처리될 수 있습니다.
5. **서버 종료/비정상 종료:** Job Object의 kill-on-close 설정이 관리 중인 작업 그룹을 종료합니다. 실행 중이던 기록이 남아 있으면 다음 서버 시작 시에도 잠급니다.

킬 스위치가 되돌릴 수 없는 범위도 있습니다. **이미 변경된 파일, 이미 전송된 외부 요청, 외부 서비스·예약 작업·기존 프로그램에 위임한 작업은 자동으로 취소되지 않습니다.** 예를 들어 별도 시스템 서비스가 생성한 프로세스는 이 Job Object 밖에 있을 수 있습니다. 이미 발송된 API 요청의 서버 측 계산과 과금을 취소했다고 보장할 수 없습니다.

작업 그룹에는 기본 **메모리 커밋 1,024 MB, CPU 비율 50%, 프로세스 32개**의 Windows 제한을 설정합니다. 화면에서 작업 메모리와 CPU 설정을 변경할 수 있습니다. 호출 수·토큰·저장량은 별도의 애플리케이션 기준이며 정확한 과금 상한은 아닙니다.

**이 구조는 수명과 자원 관리이며, 적대적인 코드에 대한 보안 샌드박스가 아닙니다.** trusted 명령은 현재 Windows 사용자 권한을 갖습니다. 같은 사용자 권한으로 제어 서버나 다른 파일에 접근하는 것을 OS 수준으로 차단하지 않습니다. 강한 격리가 필요한 작업은 별도 사용자 계정·컨테이너·VM 및 네트워크 정책을 추가해야 합니다. 기본 명령 모드는 화면에서 승인하는 `ask`입니다.

## 성장 가능성을 위해 추가한 구조

`growth.py`는 자료 전체를 모으는 대신 **다시 얻는 경로**를 보존합니다.

| 필드 | 의미 |
|---|---|
| 문제 | 어떤 상황에서 쓸 경로인가 |
| 위치 | 문서, 검색망, 로컬 파일, 도구 |
| 전략 | 검색어 구성, 필요한 정보, 실행 순서 |
| 검증 | 얻은 답이 맞는지 확인할 방법 |
| 대체 경로 | 첫 위치가 사라지거나 실패했을 때의 방법 |
| 관련 경로 | 연결해 활용할 다른 절차 |
| 버전과 평가 | 어떤 내용에 대한 성공/실패 관측인가 |

세포는 경로 후보를 만들고 검색할 수 있습니다. **경로를 평가하고 활성화하는 도구는 세포에게 제공하지 않습니다.** 사용자가 근거를 확인하고 화면에서 성공/실패를 기록합니다. 내용이 바뀌면 이전 버전의 성공 횟수를 새 버전의 증거로 사용하지 않습니다. 실패한 경로는 재검토 상태로 돌아가며, 30일간 검토가 없으면 오래된 경로로 표시합니다. 이 표시는 자동 사실 검증을 뜻하지 않습니다.

현재 검색은 키워드 일치와 사용자 관측 기반의 순위입니다. 벡터 검색, 학습된 라우터, 자동 증류는 아직 없습니다. 순위 점수는 작은 표본의 관측 요약이며, 실제 성공 확률로 보정된 값이 아닙니다. 자료가 사라져 복구가 불가능할 수 있으므로 중요한 원문·반례·평가 사례를 모두 버리는 방식으로 사용하지 마세요.

파일 변경은 **변경 의도와 백업 경로를 먼저 기록한 뒤** 파일에 적용합니다. 작업자가 중간에 종료되면 `pending` 기록으로 남아 복구 여부를 확인할 수 있습니다. 셸 명령이 한 모든 변경을 기록하는 기능은 아닙니다. 시스템 전원 손실까지 완벽한 복구를 보장하지 않습니다.

현재 해결한 문제는 제어 가능성, 자원 제한, 관측 가능성, 버전과 검증 근거 관리입니다. AGI, 무한 성장, 대형 모델보다 높은 지능, 스스로 가중치를 훈련하는 기능을 구현했다고 주장하지 않습니다. 실제 Astra 연결은 API 키가 없는 환경에서 검증하지 못했습니다.

# CLI 기능

사용자의 요청에 따라 전문 세포를 만들고, 파일·명령 도구로 작업하고, 경험과 재사용 절차를 보존하는 로컬 프로토타입입니다. Python 3.10 이상, 표준 라이브러리만 사용합니다. 별도 패키지 설치는 없습니다.

**현재 상태:** 로컬 기능과 모의 API 전송 테스트를 통과한 MVP입니다. 실제 GPT-6 Astra 호출은 API 키가 없어 검증하지 못했습니다. AGI, 대형 모델보다 높은 지능, 무한 자기 개선, 신경망 가중치 학습을 구현했다고 주장하지 않습니다.

## 바로 실행

Windows에서 `demo.cmd`를 더블클릭하면 키 없이 데모를 실행합니다. 이 데모는 고정 시나리오로 실제 런타임을 구동합니다. 모델이 스스로 계획한 결과는 아닙니다.

1. 줄기세포가 작성 세포와 관찰 세포를 생성합니다.
2. 두 세포가 병렬로 실행됩니다.
3. 작성 세포가 합계 함수와 검사 3개를 파일로 생성하고 Python으로 실행합니다.
4. 관찰 세포가 OS 정보를 조회합니다.
5. 기억과 재사용 절차 후보를 SQLite에 저장합니다.
6. 실행 기록과 결과물은 매번 별도 `demo-runs/날짜-ID/`에 보존됩니다.

실제 모델 사용은 `start.cmd`를 실행합니다. 키가 환경변수에 없으면 터미널에서 숨김 입력을 받습니다. **키를 채팅이나 소스 파일에 붙여 넣지 않아도 됩니다.** 키 자체를 프로그램이 디스크에 저장하지 않습니다. API 이용 비용이 발생하며, 해당 계정에서 모델 접근이 가능해야 합니다.

PowerShell에서도 실행할 수 있습니다. 아래 명령은 이 파일이 있는 폴더에서 실행합니다.

```powershell
python -X utf8 cell_agent.py --demo
python -X utf8 cell_agent.py --web
python -X utf8 cell_agent.py --web --task "작은 CSV 분석 도구를 만들고 테스트해 줘"
```

첫 번째는 오프라인 데모, 두 번째는 대화형 실행, 세 번째는 단일 요청입니다. `start.cmd`는 웹 검색을 활성화합니다. 검색이 필요 없으면 `--web` 없이 실행하세요.

## 몸: 컴퓨터 접근

기본 파일 도구는 이 프로그램의 `workspace/`에서 작동합니다. 생성·읽기·수정·삭제·복구를 제공합니다. UTF-8 텍스트 파일 대상이며, 재귀 폴더 삭제 도구는 없습니다. 파일 삭제와 덮어쓰기는 `state/backups/`에 이전 내용을 남기고 `change_id`를 반환합니다. 복구 시 그 이후의 변경이 있으면 덮어쓰지 않습니다.

다른 작업 폴더를 연결하려면:

```powershell
python -X utf8 cell_agent.py --root "D:\MyProjects" --web
```

`--root`는 여러 번 지정할 수 있습니다. 상대 경로는 첫 번째 루트를 기준으로 합니다.

명령 실행은 다음 세 모드입니다.

| 모드 | 동작 |
|---|---|
| `--shell deny` | 명령 실행 불가, 파일 및 기억 도구 사용 |
| `--shell ask` | 기본값. 명령과 작업 폴더를 표시하고 실행 확인 |
| `--shell trusted` | 실행 시 부여한 신뢰 범위에서 명령을 확인 없이 실행 |

```powershell
python -X utf8 cell_agent.py --root "D:\MyProjects" --shell trusted --web
```

**trusted는 호스트 컴퓨터의 현재 사용자 권한으로 프로세스를 실행하는 모드입니다.** 명령의 파일 접근은 `--root`에 격리되지 않습니다. PowerShell이나 다른 프로그램은 루트 밖에도 영향을 줄 수 있습니다. 명령이 만드는 모든 부작용을 파일 도구처럼 백업하거나 되돌려 주지는 않습니다. 이 프로토타입의 경로 검사와 역할 제한은 OS 샌드박스가 아닙니다. 관리자 권한을 자동 획득하지 않으며 OS 및 서비스 접근 제어를 우회하지 않습니다.

현재는 파일·프로세스·명령 실행을 통해 컴퓨터를 다룹니다. 화면 인식·마우스 클릭·GUI 앱 자동 조작은 아직 구현하지 않았습니다. 읽기 전용 세포는 쓰기·명령 실행·추가 분열을 할 수 없습니다. 다만 같은 호스트의 trusted 명령을 강하게 격리하는 보안 경계는 아닙니다.

## 세포, 통신, 조직

- 세포는 모델 전체의 복사본이 아니라 역할·작업·대화 상태를 가진 가벼운 작업자입니다.
- 한 번의 분열에서 최대 3개 하위 세포가 병렬 실행됩니다.
- 한 요청에서 생성되는 하위 세포는 기본 최대 8개, 분열 깊이는 2입니다. 하위 세포 전체가 공통 예산을 씁니다.
- 호스트 명령은 충돌을 줄이기 위해 직렬 실행합니다. 모델 호출과 다른 세포 작업은 병렬 실행할 수 있습니다.
- `list_cells`와 `send_message`로 같은 실행의 다른 세포를 찾고 메시지를 보냅니다. 메시지는 모델 호출 경계에서 전달됩니다. 진행 중 API 요청을 즉시 수정하는 기능은 아닙니다.
- `delegate`는 하위 세포 결과를 부모에게 반환합니다. 영구 백그라운드 프로세스를 증식하지 않습니다.
- 검증된 협업 절차는 `propose_skill`로 후보 등록할 수 있습니다. 현재의 조직은 재사용 절차이며, 독립적인 신경망이 아닙니다.

모델의 최종 문장은 `finished_unverified`로 기록합니다. 테스트 통과 증거와 모델의 완료 주장을 구분하기 위해서입니다.

## 성장: 검색, 경험, 재사용

```powershell
python -X utf8 cell_agent.py --web --learn-topic "Python CSV 파일의 오류 처리와 테스트"
```

이 명령은 **한 번의 예산 제한 학습 주기**를 요청합니다.

기존 기억 조회 → 부족한 능력 확인 → 출처를 이용한 조사 → 작은 실습 → 결과 확인 → 요약 기억 → 재사용 절차 후보의 흐름입니다. 실제 수행 품질은 모델과 도구 결과에 따라 달라집니다. 웹 검색은 OpenAI의 호스팅 도구로 연결하며, 검색 비용이 추가될 수 있습니다.

기억에는 주제·내용·출처·관측/가설 구분·저장 시간을 보존합니다. `observed`도 기록자의 주장입니다. 그 라벨만으로 독립 검증된 사실이 되는 것은 아닙니다. 동일한 주제·내용·출처·구분의 반복 저장은 중복 제거합니다.

대화 명령:

```text
/memory CSV
/skills
/stats
/quit
```

후보 검토와 활성화:

```powershell
python -X utf8 cell_agent.py --inspect
python -X utf8 cell_agent.py --activate procedure-name
```

활성화 전에 절차와 근거를 화면에 보여 줍니다. 내용이 바뀌면 기존 활성화는 취소되고 다시 후보가 됩니다. 활성 절차는 이후 세포의 문맥에 제공됩니다. 실행 중인 런타임을 자동으로 교체하지 않습니다. 신경망 가중치를 훈련하거나 수정하는 기능은 없습니다.

여러 모델의 검토를 연결할 수 있도록 `provider.response(...)` 인터페이스를 분리했습니다. **현재 구현된 실제 제공자는 OpenAI Responses 하나뿐입니다.** Claude, Codex 앱 대화, 로컬 모델을 자동으로 읽거나 호출하지 않습니다. 다른 모델 연결에는 별도 어댑터·인증·평가가 필요합니다.

## 용량과 계산량

기본 한도:

| 항목 | 기본값 | 의미 |
|---|---:|---|
| API 호출 | 20회/요청 | 모든 하위 세포 합산 |
| 하위 세포 | 8개/요청 | 실행 후 상태·기록만 남음 |
| 실행 시간 | 900초/요청 | 호출·도구 경계에서 검사 |
| API 토큰 | 80,000/요청 | 응답 사용량을 받은 뒤 합산 |
| 응답 출력 | 4,000토큰 | API 요청당 상한 |
| 호스팅 도구 호출 | 5회 | API 요청당 설정; 실 API 동작 미검증 |
| 상태 저장량 | 256 MiB | 다음 모델 호출 전에 검사하는 중단 기준 |
| 기억 | 2,000개 | 기억당 본문 최대 8,000문자 |
| 절차 | 200개 | 절차당 지침 최대 12,000문자 |
| 파일 읽기·쓰기 | 1 MB/회 | 텍스트 도구 기준 |
| 백업 | 10 MB/파일 | 변경 전 파일 기준 |
| 명령 시간 | 최대 60초 | 남은 실행 시간도 반영 |
| 명령 출력 | 약 8 MB | 주기적 검사 후 초과 프로세스 종료; 전달은 앞 24 KB |

토큰과 상태 한도는 이미 진행 중인 동시 요청의 비용·쓰기를 되돌리지 못합니다. 시간과 출력 한도도 검사 간격만큼 초과할 수 있습니다. **과금액의 엄격한 달러 상한이나 디스크 쿼터가 아닙니다.** workspace의 결과 파일, 셸이 만든 파일, 다운로드는 상태 저장량 한도에 포함되지 않습니다. API 공급자 측 사용 한도와 운영체제/컨테이너의 디스크·CPU·메모리 제한은 별도로 적용해야 합니다.

```powershell
python -X utf8 cell_agent.py --stats
python -X utf8 cell_agent.py --compact
python -X utf8 cell_agent.py --max-calls 10 --max-cells 3 --max-tokens 30000 --max-state-mb 128
```

`--compact`는 7일 지난 실행 이벤트를 gzip으로 내보낸 다음 DB에서 정리합니다. 기억·절차·복구 백업은 지우지 않습니다. 아카이브와 백업은 계속 남으므로 총용량을 영원히 일정하게 유지하는 기능은 아닙니다. 실행 중인 다른 인스턴스가 없을 때 유지보수를 수행하세요. 로그와 백업에는 작업 내용이 있으므로 해당 파일도 개인 데이터로 관리하세요.

SQLite는 단일 인스턴스 안의 여러 세포를 지원합니다. 같은 상태 폴더에서 여러 프로그램 인스턴스를 동시에 실행하는 운영 방식은 지원 범위 밖입니다.

## 저장과 외부 전송

- `state/cells.sqlite3`: 실행 기록, 기억, 절차, 메시지, 파일 변경 기록.
- `state/backups/`: 파일 변경 전 내용.
- `workspace/`: 생성한 코드와 결과물.
- API 모드에서는 작업 내용·선택된 기억·도구 결과가 OpenAI로 전달됩니다. 로컬 전용 모드가 아닙니다.
- Responses는 `store: true`와 `previous_response_id`를 이용합니다. 공급자 측 데이터 처리는 해당 계정 정책을 확인하세요.
- API 키는 요청 헤더에 사용하며, 직접 실행하는 자식 프로세스의 환경에서 일반적인 키·토큰·비밀 변수명을 제거합니다. 이것이 trusted 명령의 다른 자격 증명 접근을 완전히 막는 보안 경계는 아닙니다.
- 실행 로그는 진단용이며, 중간 상태에서의 자동 재실행·정확히 한 번 실행을 보장하는 복구 엔진은 아직 없습니다.

## 다음 단계: 경험을 작은 판단 모델로 압축

이 버전은 기억과 절차를 저장하는 기반입니다. 작은 모델의 가중치를 학습하는 증류 파이프라인은 다음 단계이며 구현되지 않았습니다.

1. 실제 작업에서 정답을 확인한 사례와 실패 반례를 수집합니다.
2. 학습용과 공개하지 않을 평가용 사례를 먼저 분리합니다.
3. 작은 학생 모델에 좁은 판단 기능을 학습시킵니다. 예: 작업 분류, 도구 선택, 오류 분류.
4. 기존 방식 대비 정답률·실패 유형·시간·메모리·비용을 비교합니다.
5. 검증된 범위만 학생에게 맡기고, 범위 밖 문제는 상위 모델로 보냅니다.
6. 이전 능력을 평가하는 회귀 사례도 남기고, 퇴보하면 이전 모델로 돌아갑니다.

‘많이 읽음’, ‘요약 파일 생성’, ‘자기 평가 점수 상승’을 지능 향상의 증거로 삼지 않습니다. 예산을 고정한 독립 평가의 개선이 필요합니다. 세포가 모든 원자료나 대형 모델을 각각 복제할 필요는 없지만, 정확도를 유지한 채 무한히 압축할 수 있다는 보장도 없습니다.
